## 2. 구현한 운용 흐름

### 시장 관찰

`config/market_research.yaml`의 9개 바스켓 구성 종목과 10개 업종 ETF를 KODEX 200과 비교한다. 반도체·은행·자동차·2차전지·헬스케어·건설·에너지화학·IT·조선·방산 ETF의 운용사 참고 링크를 설정에 남겼다. ETF 편입 종목과 산업 노출은 변할 수 있으며, 현재 관찰 목록은 과거 투자 가능 유니버스가 아니다.

- 동일 거래일 구간의 20/60/120일 수정가격 수익률과 비교지수 대비 차이.
- 직전 거래일 거래량 / 그 이전 20일 평균 거래량, 최근 20일 연율화 변동성, 120일 구간 최대낙폭.
- 각 관찰 집단에서 60일 평균선 위인 종목 수와 확인 가능한 분모. 결측을 0으로 채우지 않는다.
- 공급자, 가격 기준, 자료 기준일, 수집 시각, 설정 해시, 순위 변화. 지연·비교 불가·설정 변경을 숨기지 않는다.
- 당일 봉은 장 마감 뒤에도 제외하는 보수적인 T-1 기준. 가격 공급자의 배당 조정은 다를 수 있어 공식 총수익 지수와 같다고 보지 않는다.

화면의 **시장 자료 갱신**은 별도 프로세스에서 연구 자료만 수집한다. 120초 제한, 동시 요청 공유, 실패 표시를 제공한다. 화면의 주기 조회는 저장 자료만 읽는다. 계좌 주문 루프와 결합하지 않아 자료 수집 장애가 주문을 지연시키지 않는다.

### 투자 가설과 이벤트

`core/research_evidence.py`는 작성자가 원문을 확인한 기록을 보관한다. 자동 뉴스 피드나 LLM의 사실 판정기가 아니다.

- 가설, 기간, 반증 조건, 반대 근거, 원문 URL, 공개 시각, 실제 관측 시각, 다음 검토일, 유효 기한.
- 종목을 연결하려면 별도의 사업·이벤트 연결 근거와 출처가 필요하다.
- 저장 시 서버의 관측 시각을 부여한다. 새 버전은 추가하며 이전 버전을 덮어쓰지 않는다. 과거 조회에서 당시 없던 버전이 보이지 않는다.
- 게시 날짜만 아는 자료는 정확한 게시 시각을 만들어 넣지 않는다. `UNVERIFIED`는 정보의 시점 등이 부족하다는 뜻이다. `CURRENT`도 수익성이나 가설의 진실을 검증했다는 뜻이 아니다.
- 미래 실적 일정은 `event_at`으로 저장한다. 아직 발표하지 않은 실적을 현재의 증거로 등록하지 않는다. 이벤트가 지나면 결과 검토 대상으로 표시한다.

실제 원문을 확인한 초기 기록 두 건을 등록했다.

1. [IEA — Key Questions on Energy and AI](https://www.iea.org/reports/key-questions-on-energy-and-ai), 2026-04-16 발표. AI 확대와 전력·공급망 제약의 상호작용을 검토한다. 국내 특정 종목의 수혜를 입증한 자료는 아니다.
2. [삼성전자 3분기 가이던스](https://news.samsung.com/be/samsung-electronics-announces-earnings-guidance-for-third-quarter-2026), 2026-10-08 발표와 [공식 IR](https://www.samsung.com/global/ir/)의 10월 29일 10시 설명회 안내. 잠정 가이던스를 확정 실적으로 취급하지 않고 현금흐름·투자 지출·지속성을 후속 검토한다.

### 연구 후보 검증과 승격

기존 도구는 OOS 결과 계산 전에 추천을 만들고, 전체 기간 우수 후보와 훈련 구간 선택 후보를 섞을 수 있었다. 절대 샤프가 양수인 것만으로 비교지수 열세가 가려질 수도 있었다. 다음을 수정했다.

- 훈련 구간에서 선택한 후보의 ID를 유지하고 OOS 구간 비교지수를 다시 계산한다.
- 실제 수익률 관측수와 왜도·첨도를 DSR 계산에 사용한다. 평일 달력 일수를 관측수로 대체하지 않는다.
- OOS·다중검정·시점 유니버스 근거가 없거나 실패하면 다음 단계 추천을 보류한다.
- 새 canonical 평가와 승격에는 검증 근거와 후보·자본금·미커밋 변경을 포함한 코드 지문·설정·기간·유니버스 연결 확인을 요구한다. DSR 관측일과 학습 기간, 가능한 관측수, 252일 연율화·Pearson 첨도 규약도 확인한다. 근거가 없는 새 결과는 `research_only`이다.
- 기존 승인과 바스켓을 소급 정지하지 않는다. 과거 결과는 `legacy_unverified`로 구분하며 새 검증이 완료됐다고 표현하지 않는다.

### 재무 자료 정합성

Yahoo의 `debtToEquity`를 다시 100배 하던 오류를 수정하고, 일부 필드가 없는 다른 공급자 응답을 전체 성공으로 처리하던 경로를 보완했다. 공급자마다 부채 정의가 다르므로 필드별 출처·기준을 보존한다.

평균회귀 전략의 재무 필터도 총부채/자본 기준을 기본으로 명시한다. Yahoo의 차입금/자본을 총부채/자본으로 대체해 통과시키지 않는다. 차입금 기준이 의도라면 `debt_ratio_basis: interest_bearing_debt_to_equity_pct`를 별도로 지정해야 한다. 기준이나 수치가 없으면 매수 필터를 통과하지 못한다.

과거 날짜 조회에 현재 Yahoo 재무 값이 합쳐지거나, 마지막 날짜의 재무 점수가 과거 전 구간에 퍼지던 경로를 차단했다. 공시 시점이 없는 ROE·부채·영업이익 자료에 임의의 60일 지연을 붙여 과거에 알 수 있었다고 간주하지 않는다. 과거 재무 팩터가 자료 부족으로 비활성 상태가 되는 것은 검증 가능한 데이터의 한계를 드러내는 결과다.

현재 확보한 역사 자료만으로 재무 팩터의 최소 요건을 채울 수 없어, 역사 분석은 외부 API를 날짜마다 반복 호출하지 않고 자료 부족으로 보류한다. 실시간 분석에는 별도의 현재 관측 경로를 두어 최신 한 행에만 점수를 적용한다. 실시간 앙상블도 이 경로를 사용하며, 역사 분석과 섞지 않는다.

## 3. 실행과 재현

프로젝트 루트의 PowerShell에서:

```powershell
# 공개 가격으로 시장 관찰 자료 갱신 (주문·DB 초기화 없음)
.venv/Scripts/python.exe tools/market_research.py

# 직접 확인한 원문과 가설을 추가 (매번 새 관측 시각·버전)
.venv/Scripts/python.exe tools/research_evidence.py import config/research_theses.json
.venv/Scripts/python.exe tools/research_evidence.py list --json

# 운영 DB 사본의 실제 주문 경로 재현 (고정된 이전 검증 자료 사용)
.venv/Scripts/python.exe tools/verify_basket_snapshot_fixes.py --source-db output/basket_snapshot_review_20261013/source.db --prices-dir output/basket_snapshot_review_20261013/prices --out-dir output/research_review_20261013/new_basket_replay

# 기존 승인 평가 자료를 사본으로 읽어 새 근거 요구를 확인
```

## 5. 남은 완성도 기준

후속 구현: [공시·수급 자동 수집, 체결비용, 장기 모의 검증](RESEARCH_OPERATIONS_20261013.md). 아래 목록은 최초 조사 시점의 과제이며 후속 문서에서 구현 범위와 남은 제약을 확인한다.

이번 구현으로 시장 관찰과 연구 규율은 개선됐지만 **실제 초과수익은 아직 입증되지 않았다.** 다음은 구현됐다고 표현하면 안 되는 부분이다.

1. **공시·거시·수급의 시점 보존 자동 수집**: DART 정정 전 원문, ECOS 최초 발표와 수정치, KRX 투자자 수급을 날짜별로 보존하는 데이터 계약과 운영 점검이 필요하다. 현재 가설 기록은 수동 조사 기반이다.
2. **주문 의사결정부터 체결까지의 비용 분석**: 의사결정 가격·시각, 주문·체결·거부·미체결을 연결하고 BUY/SELL 방향별 불리한 가격 이동을 측정해야 한다. 현재 모의 슬리피지는 실측 시장 충격이 아니다.
3. **누적 연구 시행 원장과 새로운 미열람 검증 구간**: 한 실행의 DSR과 반복해서 확인한 OOS만으로 탐색 편향 전체를 제거하지 못한다. 다시 본 구간을 계속 untouched holdout이라 부르지 않는다.
4. **장기 모의 검증과 실행 가능성**: 새 관찰 지표를 운용 신호로 바꾸려면 비용·정수 수량·상승/하락 국면·회전·집중·유동성 검증과 별도의 paper 누적 관측이 필요하다. 관찰 순위가 좋아 보인다는 이유로 활성화하지 않는다.

기존 `PROFITABILITY_FINDINGS.md`의 일부 “가장 좋은 실행”, “회전이 낮을수록 수익이 높다”, “DSR 통과로 과적합이 아니다”라는 표현도 해당 표본과 가정에 한정되도록 수정했다.
